How it works

  • View results from lists every successfully processed file. The planning file is selected by default. Each entry shows the file name, the dates the data covers, and when it was uploaded.
  • Picking a review-only or older file is read-only: the plan, simulation and decision keep using the planning file. A banner says so.
  • Older files are recalculated today from the inputs saved with them, and the screen says the upload-day results were not saved.
  • Everything on screen belongs to the selected file. Switching files clears the old charts first.
  • Key results answer one question each, with source labels and "How was this calculated?".
  • Busy levels use NovaQ's fixed labels. When a plan is selected, a period above that plan's target is also flagged.
  • Calculated result (once a plan is selected): "The calculation suggests …" with the label "Calculated result · not yet checked by simulation", "Download plan report" and "Check it in Queue simulation". No decision words; the Decision comes after the simulation checks.
  • Money appears only in "What the plan changes". For separate lines, today's total cost is not available and the screen says why.
  • Warnings explain their basis and never tell the manager to add staff.

Messages users can see

  • "Recorded waiting time is unavailable because this file does not contain customer arrival and service-start times."
  • "Data period unavailable." (when the dates cannot be established from the file)
  • "Cashier-line workload applies to separate lines. This analysis uses one shared line, so workload is shown for the whole counter group."
  • "Counters can't keep up in this period, so there is no estimated wait. The line keeps growing."
  • Any missing value shows "Unavailable", never 0.
Needs backend work: B3 (results for any processed file), saved data dates, the "Use for planning / Review only" upload choice (changes NovaQ's protected rule that the latest file is the planning file), and one server-side field for busiest period by arrivals. "Compare with another file" comes later in its own spec.

Decision first, in plain words. One line per check; numbers, chart and settings open from "details". Before any check: "No decision yet" and Check the plan.

How it works

  • Three separate pages with the same header: analysis, Current | Suggested plan, and the page links.
  • One run bar on every page: operating hours, closing rule with Change, status, preview chip, Run full operation, Advanced.
  • One shared line: one continuous run of the whole day; customers keep their place, wait and unfinished checkout across periods. Preview until real service times from customer records are supported (B4b).
  • Separate lines: the existing full-day run; break states from its events.
  • Replay speed 0.25×–10×, 1× = 1 simulated minute per second (proposed), smooth gliding dots.

Which checks the decision needs

  • Separate lines: Replay of the day → Many variations → Results check, all required. "Check the plan" runs the last two and then shows the decision.
  • One shared line, period-by-period run: Results check is required; Many variations is optional.
  • One shared line, continuous run: no pass or fail rule is approved yet, so "Repeat the day" shows ranges only and no decision is shown (open decision OD-UX-13).
  • "Many variations" recalculates each period with arrivals and service speed varied; it is a calculated estimate, not simulated days.
