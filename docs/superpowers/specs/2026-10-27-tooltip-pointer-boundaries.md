# Tooltip pointer boundaries and placement

APPROVED REQUIREMENT: fix the owner's reported oversized triggers, input obstruction and persistent tooltips across NovaQ's shared help/name tooltips. Local implementation only; no production deployment or push is part of this task.

VERIFIED baseline: active checkout starts from released main 0b094a7868e5af22087f2b64caa01fe49820fb60. A read-only published-calculator browser measurement found an InfoTip wrapper 209 px wide around a 25.59375 px button. Hovering the empty wrapper opened the tip; its rectangle overlapped the input. Source has separate guest/signed-in interaction paths. Current local Docker engine is unavailable; a loopback frontend preview is used without starting or modifying operational services.

Requirements:
1. Only the actual interactive button/link and its intentional touch padding trigger hover. Empty form-row/wrapper space does not. Info buttons are 32 px on desktop and at least 44 px on small/coarse-pointer screens.
2. Info explanations prefer above their button, preserving access to the input below. Name hints prefer beside navigation controls; header hints may prefer below. Flip/clamp to available viewport space, wrap long text and allow tooltip-body scrolling. Render outside clipping cards/sidebars, retaining theme tokens and native-dialog layering.
3. One shared interaction path for guest and signed-in InfoTips. Hover opens; leaving both trigger and popup closes after a short crossing grace. The popup remains hoverable. Explicit click/tap toggles a pinned explanation; a second activation, outside pointer/focus, Escape, page/container scroll or resize dismisses it. Ordinary pointer focus must not turn a hover into keyboard persistence. Keyboard focus opens and is retained when Escape dismisses. Opening another tooltip dismisses the previous one.
4. Keep visual-only name hints separate from descriptive InfoTip accessibility semantics. Preserve existing control names, navigation handlers, description associations and keyboard/touch support. No focus trap, automatic scrolling, click forwarding or invisible full-field triggers.
5. Preserve all copy/localization/headings, calculators/queueing/statistical behavior, API/auth contracts, dependencies and data. Third-party Plotly data hover and browser-owned title hints have different semantics and are not replaced by the shared text-tooltip fix.

Accessibility references: [WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) requires dismissible, hoverable and persistent additional content. The [ARIA tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) describes Escape and focus retention; that pattern notes its work-in-progress status. The local design database provided general hover/touch guidance but no verified tooltip-boundary or React-tooltip-specific match after one narrowed retry; implementation follows inspected source and these primary references.
